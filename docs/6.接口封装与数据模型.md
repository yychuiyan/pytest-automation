# 第六步：接口封装与数据模型（基准：testing-online）

## 目标

把 **testing-online** 的真实接口封装进 `apis/`（按业务模块划分），用 `schemas/`（pydantic）校验响应结构。

> **基准项目**：`testing-online`（线上 https://testing.yychuiyan.com）
> **演示账号**：管理员 `炊烟1号 / admin123`、普通用户 `炊烟2号 / user123`
> **核心原则**：按后端接口清单封装，不要照搬 UI 页面的方法。API 测试关注的是接口契约（endpoint + 参数 + 响应），不是页面操作流程。

## 接口清单（testing-online 后端，以 `server/src/routes/*.ts` 为准）

| 模块 | 接口 | 方法 | 说明 |

| Mock | `/api/mock/*` | GET / POST | 模拟接口 |

**两个关键契约**（写 schema 前必须知道）：

1. **响应统一格式**：`{success: bool, message: str, data: ...}` —— 不是常见的 `{code, message, data}`
2. **分页格式**：列表接口的 `data` 是 `{items: [...], total, page, pageSize, totalPages}`
3. **认证方式**：登录成功后服务端下发 httpOnly cookie `auth_token`，`requests.Session` 会自动保存并后续携带（第四步 Session 封装的红利，不需要手动拼 token）

## 步骤

### 1. apis/base_api.py（接口基类）

```python
"""接口基类：所有业务接口对象继承此基类，持有共享的 HttpClient。"""

from __future__ import annotations

# HTTP 客户端（第四步封装）
from core.http_client import HttpClient


class BaseApi:
    """接口基类：只做「持有 client」这一件事，业务方法放子类。"""

    def __init__(self, client: HttpClient) -> None:
        # 一个业务 API 实例 = 一个 HttpClient（共享连接/请求头/超时/cookie）
        self.client = client
```

### 2. 按业务模块拆包（对应 testing-online 后端服务）

```text
apis/
├── __init__.py
├── base_api.py      # 基类
├── auth.py          # 认证：login / me / logout
├── users.py         # 用户管理：列表 / 新增 / 编辑 / 删除 / 改角色
├── products.py      # 商品
├── orders.py        # 订单
├── cart.py          # 购物车
└── dashboard.py     # 仪表盘统计
```

一个业务模块一个文件/包，对应后端路由文件，团队协作不冲突。

### 3. 认证接口（apis/auth.py）

```python
"""认证接口封装（testing-online）。"""

from __future__ import annotations

# requests 响应对象类型
from requests import Response

# 接口基类
from apis.base_api import BaseApi


class AuthApi(BaseApi):
    """认证接口：登录后 Session 自动携带 cookie，后续请求自动带登录态。"""

    # 登录：POST /api/auth/login，body {username, password}
    def login(self, username: str, password: str) -> Response:
        return self.client.post(
            "/api/auth/login",
            json={"username": username, "password": password},
        )

    # 当前用户：GET /api/auth/me（需登录态，Session 自动带 cookie）
    def me(self) -> Response:
        return self.client.get("/api/auth/me")

    # 登出：POST /api/auth/logout
    def logout(self) -> Response:
        return self.client.post("/api/auth/logout")
```

### 4. 用户管理接口（apis/users.py）

```python
"""用户管理接口封装（testing-online）。"""

from __future__ import annotations

# 动态参数类型
from typing import Any

# requests 响应对象类型
from requests import Response

# 接口基类
from apis.base_api import BaseApi


class UserApi(BaseApi):
    """用户管理接口：列表支持分页+搜索。"""

    # 用户列表：GET /api/users?page=&pageSize=&keyword=&role=，**query 透传为 params
    def list(self, **query: Any) -> Response:
        return self.client.get("/api/users", params=query)

    # 新增用户：POST /api/users，body 是用户字段（username/email/password/role...）
    def create(self, payload: dict[str, Any]) -> Response:
        return self.client.post("/api/users", json=payload)

    # 编辑用户：PUT /api/users/:id
    def update(self, user_id: int, payload: dict[str, Any]) -> Response:
        return self.client.put(f"/api/users/{user_id}", json=payload)

    # 删除用户：DELETE /api/users/:id（需 admin 角色）
    def remove(self, user_id: int) -> Response:
        return self.client.delete(f"/api/users/{user_id}")
```

### 5. schemas/（pydantic 响应模型）

`schemas/auth.py`：

```python
"""认证响应模型（testing-online 统一响应格式 {success, message, data}）。"""

from __future__ import annotations

# pydantic 基类：自动校验字段类型/必填
from pydantic import BaseModel


class ApiResponse(BaseModel):
    """通用响应外层：testing-online 所有接口的响应都长这样。"""

    success: bool  # 是否成功
    message: str  # 提示信息


class LoginData(BaseModel):
    """登录成功返回的数据体。"""

    username: str
    token: str
    role: str
    permissions: list[str]


class LoginResponse(ApiResponse):
    """登录响应：继承外层，data 字段类型化。"""

    data: LoginData | None = None  # 失败时 data 可能为空
```

作用：契约用例写 `LoginResponse.model_validate(resp.json())`，把「返回字段对不对」交给 pydantic 自动校验，而不是手写一堆 `has_field`。

### 6. Makefile（工程化命令入口，提前到这里）

接口一旦封装，就要有「一键跑」的命令，而不是每次敲一大串 `python -c`。**Makefile 从第八步提前到这里**——之后每加一个接口，就是「封装 → 用例 → make test」的循环：

```makefile
.PHONY: test unit contract integration smoke regression

test: ## 全量测试
	.venv/bin/python -m pytest -q

unit: ## 单元测试
	.venv/bin/python -m pytest tests/unit/ -q

contract: ## 契约测试（单接口）
	.venv/bin/python -m pytest tests/contract/ -q

integration: ## 集成测试（跨接口流程）
	.venv/bin/python -m pytest tests/integration/ -q

smoke: ## 冒烟（P0，每次提交必跑）
	.venv/bin/python -m pytest -m smoke -q

regression: ## 回归（P0+P1，每日/发版前跑）
	.venv/bin/python -m pytest -m "smoke or regression" -q
```

> 这里先立基础命令；第八步在此基础上补 `lint` / `format` / `type` 质量命令。第七步契约用例建好后，验证就变成 `make contract` / `make test`。

## ⚠️ 常见坑

1. **接口清单是唯一事实来源**：以 testing-online 的 `server/src/routes/*.ts` 为准，别凭 UI 页面反推接口——UI 可能多调好几个隐藏接口。
2. **一个业务模块一个文件/包**：别把所有接口堆进一个文件。按后端路由拆分，团队协作时不冲突。
3. **`BaseApi` 只做「持有 client」这一件事**：具体接口方法放子类，别把业务逻辑堆进基类。
4. **响应格式是 `{success, message, data}`，不是 `{code, message, data}`**：写 schema 前先看真实响应（如 `curl` 打一次接口确认），别套常见模板。
5. **登录后别手动拼 token**：`requests.Session` 会自动保存服务端下发的 `auth_token` cookie，后续请求自动带——`set_header` 反而画蛇添足。
