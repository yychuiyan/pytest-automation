# 第九步：报告与失败重跑

## 目标

接上三种测试报告，并配置失败自动重跑，提升结果可读性和稳定性。

## 步骤

### 1. 在 pyproject.toml 的 addopts 配置报告与重跑

```toml
[tool.pytest.ini_options]
addopts = [
    "-v",
    "--strict-markers",
    "--reruns", "2",               # 失败最多重跑 2 次
    "--reruns-delay", "1",         # 每次重跑间隔 1 秒
    "--alluredir=reports/allure-results",      # Allure 结果
    "--junitxml=reports/junit.xml",            # JUnit（Jenkins 趋势图用）
    "--html=reports/pytest-html/report.html",  # HTML 报告
    "--self-contained-html",                   # HTML 单文件，方便分享
]
```

三种报告的定位：

| 报告 | 用途 |
| --- | --- |
| Allure | 可视化最强，趋势/附件/步骤，本地 `allure serve` 看 |
| pytest-html | 单文件，丢给别人直接开 |
| JUnit XML | 给 Jenkins 吃，生成测试趋势图 |

### 2. 生成 Allure HTML（可选，需先装 allure 命令行）

```bash
brew install allure     # macOS
# 或从 allure 官网下载后加到 PATH

allure generate reports/allure-results -o reports/allure-report --clean
allure open reports/allure-report
```

### 3. 失败重跑说明

- `--reruns 2`：一个用例失败后最多再跑 2 次，最终仍失败才算失败
- 只对「失败」生效，`skip` / `xfail` 不重跑
- 单个用例可局部覆盖：`@pytest.mark.flaky(reruns=5, reruns_delay=2)`

### 4. 代码覆盖率（接口覆盖度是核心度量）

接口自动化最该回答的问题是「**37 个接口覆盖了几个**」。用 pytest-cov 度量 `apis/` 和 `schemas/` 的覆盖率：

```bash
uv add --dev pytest-cov     # 首次：加入 dev 依赖
uv run pytest --cov=apis --cov=schemas --cov-report=term-missing
```

输出示例：列出每个文件哪些行没被执行，最后给总覆盖率百分比。

要点：
- 覆盖 `apis/`（接口封装）+ `schemas/`（模型），衡量「封装的接口有多少被用例真正调过」
- 设覆盖率门槛（如 `--cov-fail-under=80`），低于门槛直接失败，防止覆盖率倒退
- 报告里没被覆盖的行 = 封装了但没测的接口，就是你的「待办清单」

### 5. 并行执行（pytest-xdist，缩短全量时间）

接口用例多起来，串行跑几十分钟是常态。pytest-xdist 按 CPU 核数并行跑：

```bash
uv add --dev pytest-xdist   # 首次：加入 dev 依赖
uv run pytest -n auto       # 按 CPU 核数并行
uv run pytest -n 4          # 指定 4 个 worker
```

要点：
- **只并行「无共享状态」的用例**：session 级共享的登录态、连接池在并行下各 worker 各一份，设计用例时尽量独立（第七步已注：集成用例独立登录）
- **`-n` 与 `--reruns` 有历史兼容问题**：先二选一，确认版本兼容再同时用（见坑 1）
- 数据清理类用例（第七步 teardown）并行时要注意「两个 worker 同时创建同名数据」——所以创建数据用随机生成器

## 验证

```bash
make test
ls reports/          # 应看到 allure-results/、junit.xml、pytest-html/
```

## ⚠️ 常见坑

1. **重跑与并行（xdist）别同时开**：`pytest-rerunfailures` 和 `pytest-xdist` 有历史兼容问题，先二选一，确认版本兼容再同时用。
2. **`--self-contained-html` 让 HTML 变大但可单文件分享**：如果只是本地看、不上传，可去掉减小体积。
3. **Allure 结果目录要每次清理**：不清理会残留上一次的结果，导致报告混入旧用例。CI 里记得 `rm -rf reports/`（见第十步）。
4. **重跑会掩盖不稳定用例**：重跑通过不代表用例没问题，可能是有真实 flaky。要定期看重跑率，别让 `--reruns` 变成遮羞布。
