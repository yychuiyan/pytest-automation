# 第一步：环境准备（uv + Python 3.11）

## 目标

用 `uv` 统一管理 Python 版本和依赖，把项目解释器固定在 Python 3.11，并创建 `.venv` 虚拟环境。

## 为什么要 uv

传统做法是 `pyenv` 管版本 + `pip` 管依赖 + `venv` 管隔离，三套工具。`uv` 一个工具全包了：

- 按 `.python-version` 自动下载并固定 Python 版本
- `uv sync` 一键安装依赖并创建 `.venv`
- 速度快，有锁文件 `uv.lock` 保证团队环境一致

## 步骤

### 1. 安装 uv

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装后新开一个终端，验证：

```bash
uv --version
```

> Windows 用户用 `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`。

### 2. 创建项目目录并固定 Python 版本

```bash
mkdir pytest-automation && cd pytest-automation
git init          # 初始化 git 仓库（第八步 pre-commit 需要）
echo "3.11" > .python-version
```

`.python-version` 里写的是**版本约束**（"3.11 系列"），不是精确版本号。

### 3. 初始化虚拟环境

先创建一个最小 `pyproject.toml`（第二步会补全），再同步：

```bash
touch pyproject.toml
uv sync
```

`uv sync` 会：
1. 读取 `.python-version`，下载 3.11 系列最新补丁版
2. 创建 `.venv`
3. 安装依赖（当前为空，第二步会补）

## 验证

```bash
.venv/bin/python --version
# Python 3.11.16
```

```bash
ls -la
# 应该看到 .venv/ 和 uv.lock
```

## ⚠️ 常见坑

1. **`.python-version` 写 3.11，实际显示 3.11.16**：正常现象。uv 会拉取 3.11 系列**最新的补丁版**（当前是 3.11.16），语义上就是"3.11"。
2. **系统全局 `python3` 是 3.13 也不用慌**：项目走 `.venv`，跟系统解释器无关。判断项目用的是哪个，一律看 `.venv/bin/python --version`。
3. **`python` 命令不存在（只有 `python3`）**：macOS 常见。项目内统一用 `uv run` 或 `.venv/bin/python`，不要依赖裸 `python` 命令。
4. **`uv: command not found`**：安装脚本把 uv 装到了 `~/.local/bin` 或 `~/.cargo/bin`，需要重新加载 shell（`source ~/.zshrc` 或重开终端），或把它加到 `PATH`。
