# 第八步：代码质量工程化

## 目标

用 ruff（检查+格式化）、mypy（类型）、pre-commit（提交钩子）、Makefile（命令入口）把质量卡点固化下来。

## 步骤

### 1. 完善 pyproject.toml 的质量配置

```toml
[tool.ruff]
line-length = 120
target-version = "py311"
exclude = [".venv", "reports", ".pytest_cache"]

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B", "N", "S"]
ignore = ["S101"]  # 测试框架允许 assert

[tool.ruff.lint.per-file-ignores]
"core/data_generator.py" = ["S311"]  # 测试数据用 random，非密码学

[tool.ruff.format]
quote-style = "double"
indent-style = "space"

[tool.mypy]
python_version = "3.11"
ignore_missing_imports = true
warn_unused_ignores = true
no_implicit_optional = true
```

要点：
- ruff 的 `S` 是安全规则（bandit），`S101`（测试允许 assert）和 `S311`（随机数）按需豁免
- `warn_unused_ignores = true`：防止写了没用的 `# type: ignore`

### 2. Makefile 补质量命令（基础命令第六步已建）

第六步已经建了基础命令（`test` / `unit` / `contract` / `integration` / `smoke` / `regression`），这里**补上质量命令**（lint / format / type）：

```makefile
lint: ## Ruff 检查
	.venv/bin/ruff check .

format: ## Ruff 格式化
	.venv/bin/ruff format .

format-check: ## 格式检查
	.venv/bin/ruff format --check .

type: ## mypy 类型检查
	.venv/bin/mypy core apis tests
```

> 用 `.venv/bin/` 而不是 `uv run`——与第六步基础命令风格一致，不依赖 `uv` 在 PATH（有的环境 uv 装在 `~/.local/bin`，PATH 里没有会报 `uv: command not found`）。

好处：团队所有人用同一套命令，`make help` 就能看到全部入口，不用记参数。

### 3. 配置 pre-commit

`.pre-commit-config.yaml`：

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.11.2
    hooks:
      - id: mypy
        additional_dependencies: [requests, pydantic, types-requests]
```

安装并启用：

```bash
.venv/bin/pre-commit install
```

之后每次 `git commit` 会自动跑 ruff 修复 + 格式化 + mypy，不通过就拦下提交。

### 4. 依赖安全审计

企业级要定期检查依赖有没有已知漏洞，避免带漏洞上线：

```bash
uv add --dev pip-audit       # 首次：加入 dev 依赖（uv 不在 PATH 用 ~/.local/bin/uv）
.venv/bin/pip-audit          # 扫描依赖漏洞（CVE）
```

要点：
- `pip-audit` 用公开漏洞库（OSV）扫描，CI 里可加一步 `make audit` 兜底
- 发现高危漏洞 → 升级对应依赖 → 重新 `uv sync` 生成新 `uv.lock`

## 验证

```bash
make lint
make format-check
make type
# 三者都无报错即通过
```

## ⚠️ 常见坑

1. **`# type: ignore` 要带错误码**：写成 `# type: ignore[arg-type]`，配合 `warn_unused_ignores` 才能发现"这个 ignore 已经不需要了"。
2. **mypy 对第三方库无类型**：`ignore_missing_imports = true` 会让没 stubs 的库退化成 `Any`。要更严格，给关键库装 `types-*`（如 `types-requests`）。
3. **Makefile 必须用 Tab 缩进**：recipe 行前面是 Tab 不是空格，用空格会报 `missing separator`。
4. **pre-commit 和 CI 都要跑**：pre-commit 是提交前第一道关，CI 里再跑一遍 `make lint && make type` 兜底，双保险。
