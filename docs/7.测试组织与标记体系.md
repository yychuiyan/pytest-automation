# 第七步：测试组织与标记体系

## 目标

用 conftest 组织共享 fixtures，把 `tests/` 按 **类型** 分三层，用 **marker** 做执行优先级门禁。

## 核心思想

- **目录按"测试类型"分**：unit（纯函数）/ contract（单接口契约）/ integration（跨接口流程）
- **marker 按"执行时机"分**：smoke（每次提交）/ regression（每日或发版）

不要用目录去表达"冒烟/回归"（那是 marker 的活），也不要为一个档位建一套重复用例。

## 步骤

### 1. conftest.py（全局 fixtures）

> 位置：放在**项目根目录**（和 `pyproject.toml` 同级）。pytest 会自动向上查找并加载它，fixtures 对 `tests/` 下所有用例生效。

```python
"""全局 pytest fixtures：HTTP 客户端与会话级登录。"""

from __future__ import annotations

from collections.abc import Generator

import pytest

from core.config import config
from core.http_client import HttpClient


@pytest.fixture(scope="session")
def http_client() -> Generator[HttpClient, None, None]:
    client = HttpClient(config.base_url)
    yield client
    client.session.close()


@pytest.fixture(scope="session")
def logged_in(http_client: HttpClient) -> bool:
    """登录建立 cookie 会话（testing-online 是 cookie 认证，Session 自动保存）。"""
    if not config.auth.login_api:
        return False
    payload = {"username": config.admin.username, "password": config.admin.password}
    resp = http_client.post(config.auth.login_api, json=payload)
    return resp.status_code == 200
```

要点：
- `http_client` 用 `scope="session"`，整个测试会话共用一个连接池
- `logged_in` 依赖 `http_client`，登录一次，`requests.Session` 自动保存 `auth_token` cookie，后续用例自动带登录态——**不需要手动注入 header**（testing-online 认证方式）

### 2. 目录分层

```
tests/
├── unit/           # 纯函数：crypto / data_generator / assertor / logger 脱敏
├── contract/       # 单接口：登录契约（状态码 / schema / 字段 / 错误码）
└── integration/    # 跨接口流程：登录 → me → 用户列表（真实流程串联）
```

### 3. 标记使用

```python
# tests/contract/test_login.py
import pytest


@pytest.mark.smoke
@pytest.mark.regression  # 可多贴
def test_login_success(http_client):
    resp = http_client.post(
        "/api/auth/login",
        json={"username": "炊烟1号", "password": "admin123"},
    )
    assert resp.status_code == 200
    assert resp.json()["success"] is True
```

筛选逻辑：

| 命令 | 命中 |
| --- | --- |
| `pytest -m smoke` | 有 smoke 的 |
| `pytest -m "smoke or regression"` | 有 smoke 或 regression 的 |
| `pytest -m "smoke and regression"` | 两者都有的 |
| `pytest` | 全部（忽略 marker） |

### 4. 在 pyproject.toml 注册 marker 并开启严格模式

```toml
[tool.pytest.ini_options]
markers = [
    "smoke: 核心主流程（P0 冒烟）",
    "regression: 重要功能（P1 回归）",
]
addopts = ["-v", "--strict-markers"]
```

### 5. 数据驱动（data/ + PyYAML + parametrize）

把「角色」「账号」这类差异收敛成**数据**，而不是为每组差异复制一个用例文件（示例：两个演示账号登录）。

① 准备数据文件 `data/login_cases.yaml`：

```yaml
- case: 管理员登录
  username: 炊烟1号
  password: admin123
  expect_role: admin
- case: 普通用户登录
  username: 炊烟2号
  password: user123
  expect_role: user
```

② 用例里加载并参数化：

```python
import yaml
import pytest


def load_login_cases():
    with open("data/login_cases.yaml", encoding="utf-8") as f:
        return yaml.safe_load(f)


@pytest.mark.parametrize("case", load_login_cases(), ids=lambda c: c["case"])
def test_login_role(case, http_client):
    resp = http_client.post(
        "/api/auth/login",
        json={"username": case["username"], "password": case["password"]},
    )
    assert resp.status_code == 200
    assert resp.json()["data"]["role"] == case["expect_role"]
```

效果：一个用例跑 2 组账号，pytest 展开成 `test_login_role[管理员登录]`、`test_login_role[普通用户登录]`… 而不是复制 2 个几乎一样的用例。

> 注：`data/` 已在 `.gitignore` 里忽略。含敏感数据的文件放 `data/`，脱敏的模板（如 `.yaml.example`）提交进版本库。

### 6. 测试数据清理（fixture teardown）

接口测试会创建数据（用户/商品/订单），**测完不清理会污染环境**——下次跑报「用户名已存在」、数据越积越多。企业级惯例是「谁创建谁清理」，用 fixture 的 teardown（yield 之后）自动做：

```python
# 实战示例（users 接口封装后照做）：
@pytest.fixture
def created_user(http_client):
    """创建测试用户，用完自动删除。"""
    api = UserApi(http_client)
    payload = {
        "username": DataGenerator.username(),  # 第五步随机数据，保证不重名
        "email": DataGenerator.email(),
        "password": DataGenerator.password(),
    }
    resp = api.create(payload)
    user_id = resp.json()["data"]["id"]
    yield user_id  # 交给测试用
    api.remove(user_id)  # teardown：删除，避免污染
```

要点：
- 创建数据用**随机生成器**（第五步 `DataGenerator`），避免和已有数据冲突
- `yield` 之后删除，即使测试失败也会执行清理（pytest 保证 teardown 一定跑）
- 登录这类「不创建数据」的接口不需要清理；**只有写操作（POST/PUT/DELETE）才需要**

## 验证

> 跑真实接口前先配置 `.env.test`：`BASE_URL=https://testing.yychuiyan.com`、`LOGIN_API_URL=/api/auth/login`、`ADMIN_USERNAME=炊烟1号`、`ADMIN_PASSWORD=admin123`（第七步起打线上真实接口）。

```bash
.venv/bin/python -m pytest -q                  # 全量
.venv/bin/python -m pytest -m smoke -q         # 只跑冒烟
.venv/bin/python -m pytest -m "smoke or regression" -q
```

## ⚠️ 常见坑

1. **`--strict-markers` 下未注册标记直接报错**：想加第三个自定义标记，必须先在 `markers` 里注册。
2. **空档位会导致 exit code 5**：如果 `pytest -m edge` 没有任何用例命中，pytest 以「no tests collected」退出（exit code 5），**CI 里会判失败**。所以别暴露还没用到的档位，或用 `--suppress-no-test-exit-code`（pytest 7.3+）。
3. **内置标记不用注册**：`skip` / `skipif` / `xfail` / `parametrize` 可直接用，和 smoke/regression 自由叠加。
4. **别把"档位"当"目录"**：`tests/smoke/`、`tests/edge/` 这种按执行档位建目录是 UI 测试（Playwright projects）的惯例，平移到 pytest 不自然，会导致大量重复。
