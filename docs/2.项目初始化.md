# 第二步：项目初始化（依赖与目录骨架）

## 目标

写好 `pyproject.toml`（依赖 + pytest/ruff/mypy 配置），并搭出标准目录骨架。

## 步骤

### 1. 编写 pyproject.toml

```toml
[project]
name = "pytest-automation"
version = "1.0.0"
description = "接口自动化测试框架（pytest + requests）"
requires-python = ">=3.11,<3.12"
dependencies = [
    "requests>=2.32.0",          # HTTP 客户端
    "python-dotenv>=1.0.1",      # 读 .env
    "pytest>=8.3.0",             # 测试框架
    "pytest-html>=4.1.1",        # HTML 报告
    "pytest-rerunfailures>=14.0",# 失败重跑
    "allure-pytest>=2.13.5",     # Allure 报告
    "pycryptodome>=3.20.0",      # AES 加密
    "pydantic>=2.9.0",           # 数据校验
    "loguru>=0.7.2",             # 日志
    "PyYAML>=6.0.2",             # 数据驱动
]

[dependency-groups]
dev = [
    "ruff>=0.6.0",     # 代码检查+格式化
    "mypy>=1.11.0",    # 类型检查
    "pre-commit>=3.8.0",
]

[tool.pytest.ini_options]
minversion = "8.0"
testpaths = ["tests"]
markers = [
    "smoke: 核心主流程（P0 冒烟，每次提交/PR 必跑）",
    "regression: 重要功能（P1 回归，每日/发版前跑）",
]

[tool.ruff]
line-length = 120
target-version = "py311"

[tool.mypy]
python_version = "3.11"
ignore_missing_imports = true
```

> 说明：标记（markers）、报告（addopts）、重跑等会在后续步骤逐步加进来，这里先留最小骨架。

### 2. 同步依赖

```bash
uv sync
```

### 3. 创建目录骨架

```bash
mkdir -p core apis schemas data tests/unit tests/contract tests/integration reports scripts docs
touch core/__init__.py apis/__init__.py schemas/__init__.py tests/__init__.py
```

各目录职责（先记住，后面逐步填）：

| 目录 | 职责 |
| --- | --- |
| `core/` | 框架核心：配置/日志/HTTP/加密/断言/数据生成 |
| `apis/` | 接口封装，按业务模块划分 |
| `schemas/` | pydantic 请求/响应模型 |
| `data/` | 测试数据（含敏感信息，不提交 git） |
| `tests/` | 测试用例，分 unit / contract / integration 三层 |
| `reports/` | 测试报告产物 |
| `scripts/` | 辅助脚本 |
| `docs/` | 文档 |

### 4. 创建 .gitignore

```gitignore
# 系统&IDE
.DS_Store
.idea/
.vscode/
.history/

# DSH 会话产物
.dsh/

# Python
__pycache__/
*.py[cod]
*.egg-info/

# 依赖&构建
.venv/
dist/
build/

# 测试产物
reports/
logs/
.pytest_cache/
.mypy_cache/
.ruff_cache/

# 环境&认证
.env
.env.*
!.env.example

# 测试数据（含敏感信息）：只提交脱敏模板（*.example）
data/*
!data/*.example
```

> 关键：`.venv/`、`reports/`、`__pycache__/` 必须忽略，否则会把虚拟环境和报告提交进 git。
> 说明：`data/*` + `!data/*.example` 让「数据目录整体不进库、但脱敏模板（如 `login_cases.yaml.example`）可以进库」——空目录不会被 git 跟踪，所以 `data/`、`reports/` 这类目录需要放文件才会进库。

## 验证

```bash
uv sync
.venv/bin/python -c "import pytest, requests, pydantic, loguru; print('依赖 OK')"
```

## ⚠️ 常见坑

1. **`--strict-markers` 与 markers 注册**：后续第七步会在 `addopts` 开 `--strict-markers`，届时**用到的每个自定义标记都必须先在这里的 `markers` 里注册**，否则运行时报错。
2. **依赖分两层**：运行时依赖放 `dependencies`，开发工具（ruff/mypy 等）放 `[dependency-groups].dev`。CI 装依赖时可用 `--no-dev` 跳过开发工具。
3. **先 `uv sync` 再写代码**：`uv.lock` 是锁文件，团队协作时确保每个人都 `uv sync` 而不是 `pip install`，版本才一致。
