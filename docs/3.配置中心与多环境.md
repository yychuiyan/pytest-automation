# 第三步：配置中心与多环境

## 目标

用一个 `core/config.py` 统一从 `.env` 读配置，并支持 `test / prod` 多环境切换。

## 步骤

### 1. 编写 core/config.py

```python
"""
环境配置：统一从 .env 读取配置，支持多环境切换
"""

# 让类型注解变成字符串、延迟求值。防御性写法，避免注解里引用未定义类型时报错
from __future__ import annotations

# 读取环境
import os

# 自动生成装饰器
from dataclasses import dataclass

# 路径
from pathlib import Path

# 读取.env文件
from dotenv import load_dotenv

# 项目根目录（core/ 的上一级），目的是不管在哪一级目录都能够准确找到项目根目录
ROOT_DIR = Path(__file__).resolve().parent.parent

APP_ENV = os.getenv("APP_ENV", "test")
# 从 shell/CI读取APP_ENV，加载环境
load_dotenv(ROOT_DIR / f".env.{APP_ENV}")
# 加载公共的.env，不覆盖已存在的变量
load_dotenv(ROOT_DIR / ".env", override=False)


# 封装os.getenv，目的是存在变量缺失时打日志，只需要改这个函数就可以
def _env(key: str, default: str = "") -> str:
    return os.getenv(key, default)


# 自动生成 __init__ 不用手动构造函数 frozen=True：创建后实例不可修改
@dataclass(frozen=True)
class AuthConfig:
    """登录验证相关配置"""

    login_api: str = _env("LOGIN_API_URL")
    token_field: str = _env("TOKEN_FIELD", "token")
    auth_header: str = _env("AUTH_HEADER", "Authorization")


@dataclass(frozen=True)
class UserConfig:
    """一个「账号角色」的用户名/密码 由Config负责传值，通用的角色容器"""

    username: str = ""
    password: str = ""


@dataclass(frozen=True)
class Config:
    # 全局配置单例
    env: str = _env("ENV", APP_ENV)
    base_url: str = _env("BASE_URL")
    aes_key: str = _env("AES_KEY")

    auth: AuthConfig = AuthConfig()
    # admin/unit 创建UserConfig时显示传入环境变量读取到的用户名密码
    admin: UserConfig = UserConfig(_env("ADMIN_USERNAME"), _env("ADMIN_PASSWORD"))
    unit: UserConfig = UserConfig(_env("UNIT_USERNAME"), _env("UNIT_PASSWORD"))


# 模块加载时创建一次，全项目任何地方拿到的都是同一个对象
config = Config()
```

要点：
- 用 `dataclass(frozen=True)`，配置对象不可变、类型清晰
- 账号密码等拆成 `UserConfig`，方便扩展角色

### 2. 编写 .env.example（模板，提交 git）

```bash
# ===== 环境标识 =====
ENV=test

# ===== 测试环境地址 =====
BASE_URL=

# ===== 登录认证 =====
LOGIN_API_URL=
TOKEN_FIELD=token
AUTH_HEADER=Authorization

ADMIN_USERNAME=
ADMIN_PASSWORD=
UNIT_USERNAME=
UNIT_PASSWORD=

# ===== 密钥 =====
AES_KEY=
```

### 3. 确认 .env 已忽略

第二步的 `.gitignore` 已包含下面这段，这里强调它的关键：

```gitignore
# 环境&认证
.env
.env.*
!.env.example
```

关键：`.env.*` 全部忽略，但用 `!.env.example` 把模板救回来，确保模板能进库、真实凭据不进库。

## 多环境怎么用

```bash
cp .env.example .env.test   # 测试环境
cp .env.example .env.staging  # 预发环境（可选）
cp .env.example .env.prod   # 生产环境（填真实值，已忽略不提交）

APP_ENV=test uv run pytest -m smoke   # 加载 .env.test
APP_ENV=prod uv run pytest -m smoke   # 加载 .env.prod
```

> 环境数量不限于 test/prod——`APP_ENV` 接受任意值（dev / test / staging / prod…），只要存在对应的 `.env.{APP_ENV}` 文件即可。企业级常见 dev / test / staging / prod 四环境，加一个就是 `cp .env.example .env.staging` + `APP_ENV=staging`。

## 验证

```bash
cp .env.example .env.test
.venv/bin/python -c "import core.config as c; print(c.config.env, repr(c.config.base_url))"
# test ''
```

## ⚠️ 常见坑

1. **加载顺序决定优先级**：先 `load_dotenv(.env.{APP_ENV})` 再 `load_dotenv(.env, override=False)`。`override=False` 保证公共配置不覆盖环境专属配置，实现"专属覆盖公共"。
2. **`ENV` 与 `APP_ENV` 别混淆**：`APP_ENV` 是"选哪个文件"，`ENV` 是文件里记录的语义标签。缺省时 `env` 取 `APP_ENV` 值，保持一致。
3. **`.env.prod` 千万别提交**：`.gitignore` 里 `.env.*` 必须配上，否则生产凭据会进 git 历史，删都删不干净。
4. **缺失的 `.env.{APP_ENV}` 不会报错**：`load_dotenv` 对不存在的文件静默跳过，只加载 `.env` 兜底，所以拼错环境名不会立刻报错，要留意。
